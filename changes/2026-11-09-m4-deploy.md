## 重要现场发现（与 runbook 假设不同，已按实测处理）
- ecs-sz 对外 80/443 的 nginx **不是宿主机 nginx**（1.20.1，systemd 服务 inactive 且 disabled，
  /etc/nginx 与 conf.d 为晋升前的旧配置树），而是 Docker 栈容器 `ecs-sz-nginx-1`
  （nginx 1.27，栈目录 /srv/stacks/ecs-sz，2026-11-08 家云同构晋升后的形态，与 ecs-sg 同构）。
  容器挂载：/srv/stacks/ecs-sz/nginx → /etc/nginx/conf.d(ro)；/etc/nginx/conf.d/cert → /etc/nginx/cert(ro)；
  /usr/share/nginx/html(ro)。
- 第一次把 vhost 写进宿主机 /etc/nginx/conf.d 并 reload 失败（nginx.service not active），
  发现后已删除那两个误放文件（本次会话自建，未影响任何现网），改按容器栈方式部署。
- 容器 nginx 访问宿主机 systemd 服务的路径：docker 网络 ecs-sz_default 网关 172.20.0.1，
  故 proxy_pass 用 http://172.20.0.1:8734。
- muse 的 node 是 v20.20.2（不可用）；root 的 node 是 v24.14.0（/usr/local/nodejs/bin/node，
  全局可执行），systemd 单元以 muse 用户 + 该绝对路径运行，已验证 node:sqlite 可用。

## 做了什么
1. 代码：本地打包（排除 .git、data/*.db、node_modules）→ scp → 解包到服务器 /srv/uva，
   chown muse:muse，目录 775 / 文件 664。
2. 服务：新增 /etc/systemd/system/uva.service
   （User=muse，WorkingDirectory=/srv/uva，Environment=PORT=8734，
   ExecStart=/usr/local/nodejs/bin/node src/server.js，Restart=always），
   daemon-reload + enable + start。首次启动自动建库 /srv/uva/data/uva.db 并写种子。
3. vhost（新增文件，未改任何现有配置）：
   - /srv/stacks/ecs-sz/nginx/uva-app.conf（app.outofwork.cn）
   - /srv/stacks/ecs-sz/nginx/uva-api.conf（api.outofwork.cn）
   两者 /uva/ 反代 172.20.0.1:8734，含 SSE 设置（proxy_http_version 1.1、proxy_buffering off、
   proxy_cache off、proxy_read_timeout/send_timeout 1h、Host/X-Real-IP/X-Forwarded-For/Proto）；
   app 域根路径 302 → /uva/，api 域其余路径 404。经 docker exec nginx -t + reload 生效。
4. 证书：宿主机 certbot（已装）webroot 方式新签两张 Let's Encrypt：
   - app.outofwork.cn，到期 2027-02-07 04:14:38 UTC
   - api.outofwork.cn，到期 2027-02-07 04:14:54 UTC
   按现网命名拷贝进 /etc/nginx/conf.d/cert/{app,api}.outofwork.cn.{pem,key}（key 600）；
   vhost 已升 443（TLSv1.2/1.3、http2）+ 80 全量 301 跳 HTTPS（acme-challenge 路径保留）。
   续期：certbot-renew.timer 已 enabled；新增 /etc/letsencrypt/renewal-hooks/deploy/20-uva-copy.sh
   （新文件，未动原 10-nginx-copy.sh），续期后自动把新证书拷入容器证书目录；
   注意拷后仍需 `docker exec ecs-sz-nginx-1 nginx -s reload` 才生效（现网 outofwork.cn 亦同此模式）。
